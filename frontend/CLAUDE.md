# Frontend — BlissTracker

Convenciones específicas del frontend (React 18 + Vite + Tailwind). Se carga automáticamente cuando Claude Code trabaja dentro de `frontend/`. Los conceptos de dominio (Ventas, Marketing, WhatsApp, etc.) están en `../docs/claude/` — este archivo es solo arquitectura e infraestructura frontend. Ver también `../CLAUDE.md` (raíz) para el proyecto en general.

## Environment variables (`frontend/.env.development`)
```
VITE_API_URL=http://localhost:3001
VITE_GOOGLE_CLIENT_ID=xxxx.apps.googleusercontent.com
```

## Arquitectura frontend

### Frontend (`frontend/src/`)
- **React 18 + Vite + Tailwind CSS + React Router v6.**
- **Color palette:** Custom `primary` tokens in `tailwind.config.js` based on orange (#F7931A). Status colors: IN_PROGRESS = primary (orange), PAUSED = gray, BLOCKED = red, COMPLETED = green, PENDING = gray.
- **Tests:** Vitest + React Testing Library. Test config in `vite.config.js` (`test` block). All tests in `src/tests/`.
- `api/client.js` — Axios instance: reads `VITE_API_URL`, injects JWT from `localStorage`, injects `X-Workspace: <slug>` header (derived from `window.location.hostname`), redirects to `/login` on 401.
- `context/AuthContext.jsx` — global auth state; validates token on mount via `GET /auth/me`. Exposes `updateUser()` and `switchWorkspace(slug)` (re-issues JWT for the target workspace).
- `context/WorkspaceContext.jsx` — workspace info (name, slug, status, subscription). Loaded from `GET /api/workspaces/current`. Exposes `trialDaysLeft` (derived from `trialEndsAt`) and `isSubscriptionActive`.
- `context/ThemeContext.jsx` — dark mode toggle persisted to `localStorage`.
- `hooks/useRoles.js` — fetches `UserRole` list for label lookups. Module-level cache (once per session).
- `hooks/useInactivity.js` — tracks mouse/keyboard activity; auto-pauses after 120+10 min idle on an IN_PROGRESS task.
- `utils/format.js` — shared `fmtMins()`, `activeMinutes()`, `completedDuration()`.
- `utils/linkify.jsx` — converts plain URLs in text to clickable `<a>` tags.
- **`utils/textSearch.js` — todo filtro de texto que corre en el browser pasa por acá.** `normalizeText` (minúsculas + sin tildes vía `normalize('NFD')`), `matchesSearch(texto, busqueda)`, `searchIndexOf` (devuelve la posición, para las listas que ordenan por "qué tan al principio matcheó") y `matchesAnyField([...], busqueda)`. **No escribir `x.toLowerCase().includes(q.toLowerCase())`**: ignora mayúsculas pero no tildes, y en español eso se nota — buscar "perez" no encontraba a "Pérez" ni "diseno" a "Diseño". Acá la técnica es directa (se normalizan las DOS cadenas, que están en memoria); el backend tiene el mismo problema pero no puede hacer esto y usa otra estrategia — ver `backend/CLAUDE.md` "Búsqueda de texto". Aplicado en la command palette (`scoreMatch` es el único punto por donde pasa todo su filtrado local: navegación, proyectos, personas, servicios, roles, acciones y canales), los selectores de persona/proyecto/empresa/item, el autocompletado de @menciones, RRHH, Mis Proyectos, el Wiki, Reportes, Actividad y SuperAdmin. **Lo que manda el frontend al backend como `?q=` se manda SIN normalizar** — el texto con tildes viaja tal cual y el backend lo resuelve por su lado.
- **Íconos: `components/ui/Icon.jsx` + `lucide-react` (set único de íconos de línea).** Convención: **sin ícono por defecto** — títulos, pestañas, botones con texto y secciones van solo con la palabra; el ícono se usa solo donde agrega información o reemplaza texto por falta de espacio (botones solo-ícono como cerrar/editar/eliminar, filtros de la campana, metadatos compactos como recurrente / adjuntos / comentarios, avisos). `<Icon as={Repeat} size={14} />` hereda `currentColor` y usa trazo 1.75. **No usar emojis como ícono de UI**; los emojis quedan solo en contenido del usuario (chat, reacciones, mensajes del sistema). `lib/moduleCatalog.js` guarda los íconos de módulo como componentes de lucide (`SetupHintCard`/`SegmentCards` los renderizan con `Icon`). Migración por fases: Fase 1 (menú, campana, buscador, Dashboard, ficha del proyecto, botón flotante, banners, onboarding) y Fase 2 (Marketing, informe del cliente y su PDF: tarjetas/catálogos sin ícono, métricas compactas con íconos de línea — likes, comentarios, alcance —, posiciones del top como número en vez de medallas, sellos de Meta/Google Ads con `Megaphone`, rótulos de Prioridades sin emoji también en el backend) y Fase 3 (Ventas —línea de tiempo del lead con íconos de línea por evento—, WhatsApp, RRHH, Contenido —contacto del cliente marcado con `Handshake`—, portal del cliente, Preferencias, Admin y la Nube del proyecto; `lib/fileIcons.js` `iconFor()` ahora devuelve un componente de lucide por tipo de archivo, se renderiza con `<Icon as={iconFor(mime)} />`), Fase 4 (EOS, Gamification, Calendario, SuperAdmin) y una pasada final por el resto de la app (chat y salas de voz, reuniones, reportes, actividad, pantallas de cuenta) hechas: la migración está completa. Quedan con emoji a propósito solo el contenido: los catálogos del chat (`emojiData.js`, `quickReactions.js`), Docs/wiki, las guías "¿Cómo se usa?" y las páginas públicas de marketing (Landing/Pricing/Solution*). Los símbolos de texto (✓ → ↑ ★) siguen siendo texto, no íconos. `utils/twemoji.js` queda solo como respaldo del PDF para emojis del contenido escrito por el equipo o la IA.

**Menú "⋯" compartido (`components/ui/OverflowMenu.jsx`):** el dropdown de acciones secundarias — `items` es `[{ label, onClick, danger? }]`. Se dibuja en un **portal** con `position: fixed` calculada desde el botón (se abre hacia arriba si no entra abajo) para que no lo recorte ni un contenedor con `overflow-hidden` ni el borde de la ventana, y se cierra con click afuera / Escape / scroll / resize. Nació dentro de `TaskCard.jsx` para el Dashboard y **se movió a `ui/` cuando la vista de lista de la Nube pasó a ser su tercer consumidor** (junto a `TaskCard` y `AgentTasksPanel`): importarlo desde `TaskCard` habría hecho que la Nube dependa de un componente del Dashboard. Al adoptarlo, `ItemCard` tiró su propio dropdown `absolute`.

### Navegación — barra lateral (`Navbar.jsx` + `lib/navCatalog.js`)
Desde `lg` la navegación es una **barra lateral** a la izquierda; en pantallas chicas es una barra superior con panel desplegable. Las dos salen del mismo componente y de los mismos arrays (fuente única: agregar un ítem lo suma en desktop y mobile).

**Qué secciones existen y quién las ve sale de `lib/navCatalog.js`** (`buildNavBlocks({ user, workspace, flags, gamesVisible })` → `{ primary, modules, admin, allowed, ventasBase }`), que consumen **la barra Y el buscador Cmd+K** (`hooks/useNavDestinations.js`). Antes ese criterio estaba duplicado en los dos archivos con un comentario que aceptaba la duplicación; el costo real fue que cada cambio de navegación había que hacerlo dos veces y alcanzaba con olvidarse de uno para que el buscador ofreciera una sección que el menú ya no muestra. Un ítem **sin `to`** (hoy Chat y Juegos, que abren un panel flotante) lo saltea el buscador y la barra le engancha su `onClick` por `key`: el día que tengan página propia, basta con darles `to` en el catálogo. Lo que NO vive ahí: las **sub-pestañas** de cada módulo (Marketing · GEO, RRHH · Personas…), que solo le sirven al buscador. Tests: `src/tests/lib/navCatalog.test.js`.

Los bloques:
- `primaryItems` — lo de todos los días: Dashboard, Proyectos, **Calendario** (vive acá y no en Módulos porque se usa a diario; flag + `moduleAccess.calendario`), **Chat** (abre el widget con `bliss:open-chat`, badge de menciones/no leídos de `useChat`), Actividad (punto verde en vivo), **Reportes** (`/reportes`, el propio — lo ve **todo el mundo, admin incluido**) y **Juegos** (solo si `useActiveGames().visible`, abre con `bliss:open-game`).
- **Destacados** — los proyectos con estrella (`ProjectStar`) vía `hooks/useStarredProjects.js`: caché a nivel de módulo (TTL 5 min) sobre `GET /projects`, porque Navbar se vuelve a montar en cada página. Quien cambia una estrella llama `notifyProjectStarChanged(project, starred)` (Mis Proyectos y la ficha del proyecto), que actualiza la caché sin volver a pedir nada. Punto rojo si el proyecto tiene bloqueadas.
- `moduleItems` — Ventas, Marketing, Contenido, RRHH, Finanzas (orden fijo, nunca se reacomodan según qué otros estén prendidos). Cada uno combina el feature flag con `user.moduleAccess.<key>` (ver "Acceso a módulos por rol"); Ventas mantiene `isAdmin || user?.isSales` con destino `/admin/ventas` para admin, `/ventas` para el resto.
- `adminItems` — bloque **Administración** (plegable, recordado en `localStorage` `bliss_sidebar_admin_open`): **Horas por proyecto** (`/reports`, el del equipo), EOS, Gamification, Panel. Ese ítem se llamaba "Reportes", igual que el personal: el admin veía uno solo y no tenía forma de llegar al suyo. El nombre nuevo es literalmente el subtítulo de la pantalla ("Horas registradas por proyecto frente al 100% de las horas contratadas del mes"). **EOS y Gamification quedan estrictamente `isAdmin`**, sin acceso configurable por rol.
- `workspaceItems` — el selector de workspace del encabezado de la barra (otros workspaces con punto rojo si tienen novedades + "Crear workspace"). En mobile va dentro del menú de la persona.
- `profileSections` — el menú de la tarjeta de la persona al pie (Perfil, Preferencias, Facturación solo admin, Ver como miembro, Super Admin, Cerrar sesión). Los ítems/secciones con `mobileOnly` (Docs, Workspaces) en desktop ya están en otro lado.

**Encabezado y pie de la barra:** arriba el workspace con su selector, el campo "Buscar o ir a…" (dispara `bliss:open-palette`, que escucha `GlobalShortcuts` — el mismo buscador que Cmd/Ctrl+K) y el botón **+** de nueva tarea (`bliss:open-add-task`). Abajo una fila de herramientas — campana (`NotificationBell` con `buttonClassName`/`panelClassName`, que abre su panel hacia el costado), pizarra (`bliss:toggle-notes`, que escucha `NotesBoard`; solo si `notesBoardEnabled`), Docs, tema y colapsar — y la tarjeta de la persona.

**Colapsada:** el botón del pie la deja en 64px de solo íconos (tooltips por `title`, Destacados ocultos, los bloques separados por una línea, punto rojo sobre el ícono si hay algo pendiente). Se recuerda en `localStorage` `bliss_sidebar_collapsed` — es cómo mirar, no un dato del workspace.

**Por qué ninguna página cambió su layout:** la barra es `position: fixed` y su ancho se reserva con el padding del `body` desde `index.css`, gatillado por las clases `has-sidebar`/`sidebar-collapsed` que Navbar pone en `<html>` en un `useLayoutEffect` (y saca al desmontarse, así login/landing/portal no quedan corridos). Los overlays `fixed inset-0` siguen cubriendo toda la ventana. Lo que sigue en el flujo de la página son los banners, la barra superior de mobile y la pizarra (cuya flecha de abrir/cerrar se oculta desde `lg`, donde la abre el botón de la barra).

**`FloatingDock`:** desde `lg` su botón flotante se oculta (Nueva tarea, Chat y Juegos ya están en la barra); en mobile sigue igual. Los paneles reales (chat, juegos, voz) se montan siempre. Recibe `games` desde Navbar para no sumar otro polling de `/gamification/active`.

**Atajos de teclado globales:** `GlobalShortcuts.jsx` se monta una sola vez en `App.jsx` (dentro de `<BrowserRouter>`, después de `<Routes>`) y maneja atajos para todo usuario autenticado en un subdominio de workspace (`enabled = !!user && isWorkspaceSubdomain()`). Maneja únicamente: `N` → nueva tarea (renderiza un `AddTaskModal` global, sin proyecto bloqueado), `?` → overlay de ayuda (catálogo agrupado en Tareas / General), `Esc` → cierra la ventana abierta. **Se sacaron los atajos de navegación** (`Shift+D/Y/A/M/R` a Dashboard/Proyectos/Actividad/Marketing/Reportes) **y las acciones de tarea con Shift** (`Shift+I/C/P/B`, que vivían en `Dashboard.jsx`) — en la práctica no se usaban; simplifica ambos componentes y evita mantenerlos sincronizados con el menú/la UI. El catálogo de ayuda también lista, **solo como documentación**, un atajo manejado por otro componente: `Ctrl/Cmd+B` (pizarra, en `NotesBoard.jsx`).

**Buscador global (Cmd/Ctrl+K, `CommandPalette.jsx`):** navegación (`useNavDestinations`, sobre `lib/navCatalog.js`; cada destino puede traer `keywords` — los nombres por los que la gente busca algo que en el menú se llama distinto, p. ej. "mis proyectos" → Proyectos —, que `scoreMatch` concatena al label igual que ya hacía con las acciones rápidas), proyectos, personas, canales de chat (`useChat().channels`, abren el widget vía `bliss:open-chat`), leads/empresas de Ventas, servicios/roles (solo admin → `/admin?tab=`), **acciones rápidas** (nueva tarea, agendar reunión, abrir chat, cambiar tema — se listan sin escribir) y un bloque server-side `GET /api/search?q=` (`search.controller.js`: tareas, piezas de Contenido, reuniones de Calendario y archivos de proyecto; Contenido/Calendario respetan flag + `moduleAccess`, Archivos `Project.filesEnabled`). Una query que es **sólo un número** (`29943`, `#29943`, `tarea 29943`) se resuelve como el **número de tarea** (`Task.id`, el que muestra el detalle): el backend la busca como id exacto y la pone primera. Es la referencia con la que una tarea circula fuera de la app — un agente dice "mirá la tarea 29943" —, así que esquiva el mínimo de 2 caracteres; si el número es más corto que ese mínimo la búsqueda por texto se saltea entera, porque buscar "7" devolvería cualquier tarea con un 7 en la descripción. Elegir una tarea dispara `bliss:open-task` (lo escucha `GlobalShortcuts` y abre `TaskCommentsModal` sin navegar, también para tareas completadas; ahí el número se muestra junto al proyecto y se copia con un click). Deep-links que consume: `/calendario?event=<id>` / `?schedule=1`, `/admin/ventas?tab=empresas&company=<id>`, `/proyectos/:id?infoTab=archivos&fileId=`, `/contenido?projectId=&piece=`.

**Sin atajos de acciones de tarea:** `Dashboard.jsx` tenía un listener propio para `Shift+C/P/B/I` (completar/pausar/bloquear/iniciar la tarea en curso) — se eliminó junto con los de navegación de `GlobalShortcuts` (mismo motivo: en la práctica no se usaban). Las acciones de tarea se disparan solo desde los botones de `TaskCard`. Cuando se crea una tarea desde el modal global, `GlobalShortcuts` emite el evento `window` `bliss:task-created` (detalle = la tarea); `Dashboard.jsx` lo escucha y recarga con `loadToday()` (el botón "+ Agregar tarea" del propio Dashboard usa su modal local y **no** emite el evento, así no hay doble refresco).
